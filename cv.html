What I do

Infrastructure, end to end.

My work sits underneath the product: cloud and Kubernetes topology, the deployment and CI substrate, observability and alerting, network and identity, compliance scope, the data platform, and the internal tooling engineers use every day.

Most of it is migration work on systems that move real money, executed without a maintenance window — staged, reversible, staging first. The rest is a standing reliability and security practice, and the developer platform that lets a small team ship safely across a large service estate.

I work in the open and in writing. Every programme gets a plan document, a decision record and a post-mortem trail — and when a decision gate says don't migrate, that gets written down too.

Focus areas

Where the work goes.

Developer platform

Brokered, audited access

An internal read-only CLI for cloud, clusters, databases and workflows — backed by an identity-aware credential broker, so long-lived keys give way to short-lived, per-person credentials that are audited by construction. Engineers and AI agents get the same surface, the same allowlist and the same audit trail.

Network & mesh

Ingress onto a service mesh

Moved production ingress off a legacy reverse proxy onto a mesh gateway, host by host, each with its own cutover and rollback point — then into ambient mode, retiring per-service network shims and enabling strict mutual TLS namespace by namespace.

Observability

Signals you can act on

A self-hosted metrics, logs and traces stack managed entirely as code, with per-workload dashboards and alerting, and availability SLOs backed by multi-window burn-rate alerts. Also ran a fully costed evaluation against the incumbent vendor — and recorded the honest answer rather than the exciting one.

Security & compliance

Payment-card scope

Card-data isolation and encrypted retrieval, sensitive values kept out of logs, reversible crypto replaced where hashing was correct, authorisation gaps closed on money-movement endpoints, and standing access reduced to least privilege across the organisation.

Delivery

Guardrails, not gatekeeping

A shared CI layer across every repository — static analysis, linting, migration-ordering checks and mutation testing, reported inline on the diff. Canary deploys behind automated latency gates, disruption budgets on the transaction hot path, and an automated review agent that reads pull requests before a human does.

Migrations

Moving the foundations

A rebuilt network topology, the workflow engine brought in-house, the message broker migrated, analytics moved onto a lakehouse, and a sustained cloud cost-reduction programme — each one landed incrementally, alongside the system it replaced rather than instead of it.
